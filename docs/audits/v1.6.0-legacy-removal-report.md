# v1.6.0 Legacy Removal Report

Status: **final for v1.6.0**.

Rule: preserve history, preserve promised compatibility, remove obsolete implementation, migrate old state, do not carry dead architecture forever.

Classification: `REMOVE_NOW`, `MIGRATE_THEN_REMOVE`, `DEPRECATE_NOW_REMOVE_NEXT_MAJOR`, `KEEP_COMPATIBILITY`, `KEEP_HISTORY_ONLY`.

## Audit method

Searched `src/` for `legacy`, `deprecated`, `obsolete`, `compat`, `alias`, `fallback`, `temporary` and version markers (94 hits), then traced each runtime path to its writer, reader, public contract and tests. A marker word alone never decided removal.

## Removed

| Item | Why safe | Evidence |
|---|---|---|
| `handleMcpMessage` (`@deprecated` test-only alias of `handleLegacyMcpMessage`) | internal; only consumer was a test | test imports the real function; MCP smoke unchanged |
| `brainExportExists`, `safeJsonParse`, `compactJsonToon` | zero consumers | [refactor map](v1.6.0-refactor-map.md) |
| 10 copies of the ASCII slug algorithm, 22 copies of `exists()` | replaced by `stableSlug` / `pathExists` with equivalence tests | `tests/v160-simplification.test.ts` |
| 114 literal host branches and 6 duplicated host-mapping helpers | replaced by the host adapter registry; 40 captured outputs equivalent | [host compatibility](../rails/hosts/host-compatibility-rail.md) |
| Approved-memory mirror write into `memory/memory.jsonl` | `approved.jsonl` is canonical; mirror caused duplicates and stale leaks | `tests/v160-legacy-cleanup.test.ts` |

## Migrated then removed

| Old state | Migration | Runtime path removed |
|---|---|---|
| Approved memory recorded only in the legacy log (`memory.jsonl` lines with `approved: true` / `[approved]`) | `memory-approved-canonical-v1.6`: detect legacy-only approvals, append to `approved.jsonl` atomically, verify record count, write receipt `.soturail/migrations/memory-approved-canonical-v1.6.json`; idempotent; the legacy log is kept as history | dual-read in `context-pack.ts` and `cache-normalizer.ts`; both now use the single reader `readApprovedMemory` |

Fixed while migrating (trust bugs, not just debt):

- every approved memory appeared **twice** in context packs and cache payloads;
- approved memory marked `stale` still appeared as approved through the legacy mirror, and the canonical reader never filtered `stale`. Context packs now omit stale entries and say how many were omitted.

## Deprecated (removal target v2.0.0)

| Item | Replacement | Notice |
|---|---|---|
| `skills export --layout flat` (v1.5 single-file export) | `--layout portable` (Agent Skills directories, host projections) | stderr deprecation notice |
| host ID `gemini-legacy` | `gemini` (same context target; Gemini CLI loads `.agents/skills`) | stderr notice on `agents` / `report` commands; declared as `deprecated` in the adapter |
| authoring new v1.5 packs (`skills init|template|build` → `.soturail/skills/<id>/skill.yml`) | portable `.agents/skills/<name>/SKILL.md`; `soturail skills migrate <id>` copies a pack without modifying it | catalog reports migrated packs as `legacy_superseded` |
| legacy MCP negotiation (`2024-11-05` initialize path) | official SDK, protocol `2026-07-28` | documented v1.5 public compatibility contract — cannot be removed in a minor release |

## Compatibility retained

| Item | Why |
|---|---|
| v1.5 Skill Rail pack reader (`skill.yml` + `SKILL.md`) | persisted user state; adapted into the single Skill model without rewrite |
| `memory add` / free-form `memory.jsonl` log | public command and user history; only the approval mirror was removed |
| keyword `skills suggest/route`, `routeContext` | offline fallback / benchmark baseline; demoted from authority in CP6 |
| dual agent export directories (`.soturail/exports/agents/<host>` and `.soturail/agents/<host>`) | both documented since v1.1; consumers unknown |
| raw metadata `legacy-unreported` defaults | raw logs recorded before v1.5 remain inspectable |
| v1 Capability Registry JSON fields | `capabilities list --json` consumers; v2 catalog is additive |

## Historical only

`CHANGELOG.md`, `docs/releases/RELEASE_NOTES_v*.md`, `docs/getting-started/migration-v0.5.md`, `migration-v1.md`, `migration-v1.5.md`, `docs/audits/v1.5.0-preimplementation-audit.md` and the v1.4 command reference stay as history. Current docs point to the v1.6 architecture; [Skill Rail 2.0](../rails/skills/skill-rail-2.md) is now labeled as the historical pack format.

## Deferred

| Item | Reason |
|---|---|
| merging `agentProfiles`, `capabilityOverrides` and the adapter registry into one table | three already-data tables with published JSON shapes (`agents matrix`); merge after golden fixtures for every field |
| `readJson` helper variants | semantics differ (null vs throw vs `{}`) |
| mode-specific install generators (Claude MCP/hooks, Cursor rules) | host-specific file content; candidates for adapter-owned generators |
