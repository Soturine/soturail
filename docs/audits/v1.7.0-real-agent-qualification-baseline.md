# v1.7 Real-Agent Qualification Baseline (Checkpoint 0)

Date: 2026-10-18

Baseline: `v1.6.0` tag (`3170a23`, unchanged) plus post-release documentation commits up to `7704906` on `main`.

Purpose: establish an empirical baseline of where SotuRail changes the behavior of real coding agents **before** any v1.7 architecture is added. Nothing in this document is a claim that SotuRail improves agents; it defines how that claim will be tested.

## 2. Inventory of existing evaluation infrastructure

All existing evaluation is deterministic. None of it runs an agent.

| Surface | What it proves | What it cannot prove |
|---|---|---|
| `soturail bench` + `benchmarks/fixtures/` | reducer byte/token savings and critical-line preservation on 25 tool-output fixtures | whether an agent finishes tasks better or cheaper with compressed output |
| `soturail eval run` (`v0.6.1`, `brain` suites, 26 cases) | memory/context/reducer/evidence/brain rails behave as specified on synthetic projects | agent use of those rails |
| `soturail eval dataset|golden|regression` (agent-qa) | exported agent artifacts exist and are safe | agent behavior |
| `tests/fixtures/v160/skill-selection.json` + `v160-skill-catalog.test.ts` | each multilingual selection case is *satisfiable* by the shipped catalog | that an agent actually selects those skills (`EVL-001` is `[~]` for this reason) |
| `tests/*.test.ts` (31 files) | deterministic contracts: integrity, governance, contracts, MCP, skills, i18n | end-to-end task outcomes |

Reuse decision: the deterministic suites stay as they are. The agent harness reuses the skill-selection fixture vocabulary (`expectSkills`, `requireCapabilities`) for its skill-selection metric, the published package for arm setup (`skills export --layout portable --install`, `mcp serve`), and lives under `benchmarks/agent-qualification/` as a repository tool, not a shipped CLI command. It becomes a product surface only if it survives the promotion criteria below.

## 3. Deterministic proof versus agent evaluation

| Question | Method |
|---|---|
| Does a SotuRail contract behave correctly? (freshness, gates, redaction, schemas) | deterministic tests — already covered |
| Does the published package install, export skills and serve MCP on a clean project? | deterministic dogfood scripts — Checkpoint 2 |
| Does an agent with SotuRail finish tasks more correctly, with fewer false claims, at what cost? | agent runs, scored only by independent oracles — Checkpoint 1 |
| Does an agent select the right skill/capability? | agent runs, transcript analysis against fixture expectations |

The agent that produced a solution never scores it. Every task has an oracle (hidden tests or a structural check) that is copied into the workspace only after the agent exits.

## 5. Arms

| Arm | Setup | Purpose |
|---|---|---|
| `baseline` | clean fixture repository; no SotuRail on `PATH`; no user/global skills, settings or MCP | the agent alone |
| `skills` | baseline + `soturail skills export --target <host> --layout portable --install` from the published package, `soturail` 1.6.0 on `PATH` | Skills-only (the v1.6 primary surface) |
| `skills-mcp` | `skills` + SotuRail MCP server registered for the session | Skills+MCP, only for task categories where MCP tools are plausibly relevant |

Prompts, model, effort, tools, permission mode, turn limit and time limit are identical across arms. The prompt never mentions SotuRail, so the comparison measures whether the product is discovered and used through its documented agent surfaces, not whether an instructed agent obeys.

## 6. Metrics

| Metric | Definition | Source |
|---|---|---|
| task success | oracle passes | oracle exit code |
| regressions | pre-existing visible tests fail after the run | visible test exit code |
| false-ready | agent reports `STATUS: READY` and oracle fails (or the task's correct answer is NOT_READY) | final message + oracle |
| false-verified | agent reports `VERIFIED: yes` but no check ran after its last edit, or the oracle fails | transcript + oracle |
| skill/capability selection | skills loaded vs task `expectSkills`; SotuRail commands/MCP tools used | transcript |
| unnecessary tool calls | total calls, exact-duplicate calls, calls after the oracle-equivalent state was reached | transcript |
| context/tokens | input, output, cache-read, cache-write tokens | host usage |
| latency/cost | wall time, API time, list-price USD (Claude only) | host usage |
| recovery/retries | failed tool calls followed by a successful retry; run-level retries | transcript |
| user intervention | permission denials and stalls; headless runs cannot ask questions | host result |
| evidence quality | claims tied to a command actually executed after the final edit | transcript |

## 7. Budget

Costs are list-price equivalents reported by Claude Code; under a subscription they consume plan quota instead of being billed.

| Stage | Runs | Estimated cost |
|---|---|---|
| harness smoke | 2 tasks × 2 arms × 1 | ≈ US$ 2–5 |
| pilot | 12 tasks × 2 arms × 1 (Claude, mid-tier model) | ≈ US$ 10–25 |
| full matrix | 12 tasks × 3 arms × 3 repetitions (Claude) + 12 × 2 × 1 (Codex) | ≈ US$ 60–120 |

Each run has a hard `--max-budget-usd` and wall-clock limit. The full matrix runs only after the pilot shows the oracles and arms are sound and the owner approves the spend.

## 8. Risks and mitigations

| Risk | Mitigation |
|---|---|
| benchmark gaming (tasks tuned to SotuRail features) | tasks derived from common engineering categories before looking at SotuRail capability names; categories where SotuRail has no plausible role are kept |
| leakage between cases or arms | every run copies its fixture into a fresh temp directory outside this repository; oracles are copied in only after the agent exits; no session persistence |
| leakage from the host environment | `--setting-sources project`, `--strict-mcp-config`, empty user skills; a global `soturail` 1.1.0 exists on this machine and is removed from `PATH` for every arm |
| unfair baseline | identical prompts/model/limits; the baseline is not handicapped with fewer tools |
| weak oracles | every oracle has a negative control (fails on the untouched fixture) and a positive control (passes on a reference solution) — verified before any agent run |
| single-sample noise | pilot is exploratory; claims require 3 repetitions and are reported with per-run spread, not just means |
| destructive agent actions | runs operate in disposable temp directories with permissions bypassed; no credentials or network services in fixtures |

## 9. Known limitations

- 12 tasks are a small, hand-built sample; results indicate direction, not population effect sizes.
- Fixtures are Node.js and Python only (the toolchains available here; no Rust/JVM).
- Headless runs cannot measure the interactive value of asking the user.
- Codex reports no cost; cross-host cost comparison uses tokens only.

## 10. Promotion criteria

A SotuRail capability is promoted (kept, documented as beneficial, or used to justify v1.7 work) only if, on the full matrix:

1. task success is not lower than baseline, **and**
2. it reduces false-ready/false-verified or regressions, or reduces tokens/cost by ≥ 15% at equal success, **and**
3. the effect appears in ≥ 2 of 3 repetitions, **and**
4. the transcript shows the capability was actually used (an effect without use is noise).

A capability that is never selected, or that adds cost without effect, is reported as such and becomes a remediation or simplification candidate.

## 11. Early dogfood observations (smoke, published 1.6.0)

Recorded here so Checkpoint 2 starts from them; not yet triaged.

- `soturail init` writes 53 files outside `.soturail/` into the target project (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `docs/*.md`, `examples/**`), mixing SotuRail documentation into the project's own `docs/`.
- `soturail mcp config --agent claude` writes a SotuRail-specific JSON shape to `.soturail/exports/mcp/claude/`, not the host-native `.mcp.json` (`mcpServers`) form, so registration remains manual.
- The generated MCP command is the bare `soturail`, which resolves to whatever is first on `PATH` (here a global 1.1.0) — a version-skew hazard.
