## 4. Gates and verdicts

| Gate | Question | Output | Decision |
|---|---|---|---|
| Authority (`GovernanceProvider`) | may the actor/capability act? | `allow\|deny\|unavailable` + reasons | KEEP meaning |
| Readiness (`evaluateReadiness`) | is the engineering evidence sufficient for this contract? | `ready\|not-ready` + reasons | KEEP meaning |
| Dual Gate | both above | `allow\|deny` | KEEP |
| Execution Envelope | is the executed payload the evaluated payload? | attested / `NOT_ATTESTED` | KEEP |
| Evidence status | what was observed? | `verified\|unverified\|blocked\|inferred\|stale` | KEEP; add candidate boundary (CP8) |
| Artifact freshness (`assessArtifactFreshness`) | does an artifact match the workspace? | freshness | DEFER → wire into the shared decision base in CP8 (currently unused) |
| Policy queue | did a human approve? | `approved\|rejected` | KEEP (human authority input) |

Shared infrastructure, not shared meaning: reasons are free-text strings in every gate. CP8 introduces one typed decision base (`kind`, `outcome`, `reasons: [{code, message}]`, `evaluatedAt`, `workspaceFingerprint`, `artifactRefs`) that authority, readiness, freshness and evidence sufficiency results extend. No new gate type is added for its own sake; quality reports stay reports.

## 8. Mental model target for agents

```text
USER -> AI AGENT / SEMANTIC WORKER -> SKILL -> CAPABILITY
     -> NATIVE FACT / PROVIDER -> ARTIFACT + PROVENANCE
     -> TRUST / EVIDENCE / READINESS -> ACTION / RESULT
```

Rails remain documentation vocabulary; agents see Skills and capabilities, not internal rail modules.
